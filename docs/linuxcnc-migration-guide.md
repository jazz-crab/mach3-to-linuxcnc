# Переход с Mach3 на LinuxCNC — общий гайд

Машинно-независимая инструкция: как перенести станок с проприетарного Mach3 на
свободный LinuxCNC. Конкретика по конкретным станкам — в `machines/<модель>/`.

---

## 1. Mach3 vs LinuxCNC

| | Mach3 | LinuxCNC |
|---|---|---|
| Лицензия | проприетарная | **свободная** (GPL) |
| ОС | Windows | GNU/Linux (Debian/Ubuntu) |
| Конфигурация | `.xml` профиль + GUI-поля | текстовые `.ini` + `.hal` |
| Движок движения | «чёрный ящик» | **HAL** — открытая связка компонентов |
| Realtime | своя реализация | RT-ядро (PREEMPT_RT или RTAI) |
| Порты | LPT, USB, Ethernet | LPT, Mesa Ethernet/SPI, и др. |

Ключевое: **все настройки из Mach3 переносятся в LinuxCNC почти один в один** —
распиновка порта, шаги на миллиметр, скорости. Нужно только перевести их в
новые поля.

## 2. Что фактически переносится

Из Mach3 (`Config → Ports and Pins`, `Motor Tuning`, профиль `.xml`):

- **Раскладка пинов** LPT (STEP/DIR/ENABLE/PWM/реле/концевики) — номера пинов
  **совпадают** с LinuxCNC (физический контакт DB25).
- **Steps per Unit** (шаг/мм) → поле `SCALE`.
- **Velocity / Acceleration** → `MAX_VELOCITY` / `MAX_ACCELERATION`.
- **Инверсии** сигналов (активные уровни) → флаги `Invert`/`setp ...-invert`.
- Адрес LPT-порта (обычно `0x378`), микрошаг с DIP драйвера, шаг винта.

## 3. Чеклист «снять со старой системы»

- [ ] Mach3 `.xml`-профиль (или скриншоты Ports & Pins).
- [ ] Motor Tuning для каждой оси (шаг/мм, vel, accel).
- [ ] Фото платы/драйвера: подписи пинов, DIP-микрошаг, перемычки реле.
- [ ] Адрес LPT в BIOS (`0x378`), режим порта.
- [ ] Схема подключения шпинделя/частотника (0–10 В, реле пуска).

## 4. Оборудование

- **LPT-контроллеры** (как у Mach3) работают в LinuxCNC напрямую через
  `hal_parport`: номера пинов не меняются.
- У разных плат **свои активные уровни** и требования к длительности импульса
  STEP — смотри РЭ платы (запас 10–15 мкс обычно надёжен).
- **Современная альтернатива:** платы Mesa (Ethernet/SPI) дают аппаратный
  step-генератор и лучшую стабильность, чем софт-степпинг по LPT.

## 5. Основы LinuxCNC, которых хватает для старта

### HAL-термины

| Термин | Смысл |
|--------|-------|
| `component` | модуль (например `stepgen`) |
| `pin` | вход/выход компонента (`stepgen.0.step`, `parport.0.pin-02-out`) |
| `signal` | именованный «провод» |
| `net` | соединить сигнал с пинами |
| `setp` | выставить параметр (например инверсию) |
| thread | realtime-поток, в который вешаются функции |

### Ключевые компоненты

- `hal_parport` — работа с параллельным портом (`loadrt hal_parport cfg="0x378"`).
- `stepgen` — генерация импульсов STEP/DIR для шаговых осей.
- `pwmgen` — ШИМ для шпинделя (через ЦАП платы → 0…10 В на частотник).
- `pid` — для сервоосей.

### Формула SCALE (шаги на миллиметр)

```
SCALE = полных шагов/об × микрошаг / шаг винта (мм/об)
```

Пример: двигатель 1.8° (200 шагов/об), микрошаг 1:8, винт 5 мм/об →
`200 × 8 / 5 = 320 шаг/мм`. Проверка линейкой: `G0 X100` → рулетка ≈ 100 мм;
при ошибке на 98 мм SCALE умножить на `100/98`.

### Realtime и latency

- Нужно RT-ядро: `linux-image-rt-amd64` (PREEMPT_RT). Проверка: `uname -r`
  содержит `-rt-`.
- `latency-test` показывает джиттер. Для софт-степпинга по LPT желательно
  **< 30–50 мкс** максимума. В StepConf это поле **Base Period Maximum Jitter**.

## 6. Типовой порядок перехода

1. **Установка системы:** Debian (Trixie) + RT-ядро + `linuxcnc-uspace`.
   Без интернета — офлайн-набор из `offline/` этого репозитория.
2. **Latency test:** записать max jitter, не запускать LinuxCNC параллельно.
3. **LPT:** BIOS (вкл, `0x378`, EPP/ECP/SPP), blacklist модуля `lp`,
   пользователь в группах `dialout,plugdev`.
4. **StepConf** (мастер): mm, XYZ, Driver Type=Other, пины из чеклиста,
   SCALE по формуле, скорости скромные (старт 30–50 мм/с).
5. **Проверка пинов** (`halshow`): джог → мигают `pin-02-out`/`pin-06-out` и т.д.
6. **Одна ось** на малой скорости и зоне → поднять vel/accel, минус 10–15%.
7. **Направления и лимиты:** сход с Invert входов концевиков; soft limits.
8. **Homing:** медленно, latch, home внутри soft limits.
9. **Шпиндель:** 0–10 В на частотник, реле пуска; калибровка S-кода.
10. **Холостой G-code**, затем реальная обработка.

## 7. Перенос настроек: Mach3 → LinuxCNC

| Mach3 | LinuxCNC |
|-------|----------|
| Steps per Unit | `SCALE` (в .ini / StepConf) |
| Velocity | `MAX_VELOCITY` |
| Acceleration | `MAX_ACCELERATION` |
| Port/Pin Assignments | StepConf «Parallel Port Setup» |
| Active Low | флаг `Invert` на пине |
| Kernel Speed / pulse width | Step Time / Step Space (base thread) |
| Debounce | `debounce` HAL-компонент на входах |

## 8. Частые проблемы

| Симптом | Причина → решение |
|---------|-------------------|
| Нет реакции на LPT | BIOS LPT/адрес, blacklist `lp`, RT-ядро, latency |
| Ось не едет | ENABLE, питание, DIP, аварийный светодиод драйвера |
| Потеря шагов | скорость/ускорение ↓, Step Time ↑, микрошаг, ток |
| Едет не туда | Invert DIR или знак pitch |
| Сразу limit/following error | инверсии входов концевиков, мягкие лимиты, SCALE |
| Шпиндель не крутится | реле, перемычки платы, клеммы пуска частотника |
| Обороты не те | PWM rate, калибровка, `C11`/`C15` частотника, полярность 0–10 В |

Полезные команды:

```bash
halcmd show pin parport
halcmd show pin stepgen
dmesg | tail -50
```

## 9. Где лежат конфиги

- StepConf создаёт `~/linuxcnc/configs/<имя>/` с `*.ini` и `*.hal`.
- `custom.hal` / `custom_postgui.hal` — свои доработки, StepConf их не затирает.
- Пример инверсии пина: `setp parport.0.pin-06-out-invert true`
