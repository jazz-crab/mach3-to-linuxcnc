# Офлайн-установка LinuxCNC на станок (без интернета)

ПК станка не подключён к сети. Полный набор: скачиваешь пакеты на любом
подключённом ПК, кладёшь на флешку, запускаешь скрипт на станке — через ~час
получаешь Debian Trixie с LinuxCNC, рабочим столом openbox и пользователем
`cnc` / `cnc`, готовый к настройке станка.

**Состав:**

```
offline/
├── fetch-packages.py   # качает .deb + зависимости (python3, любой ОС)
├── setup-machine.sh    # ставит и настраивает систему на станке
└── dotfiles/           # клавиши, автозапуск LinuxCNC, Thunar ПКМ-меню
```

---

## Шаг 1. Скачать пакеты (на ПК с интернетом)

```bash
python3 fetch-packages.py
```

По умолчанию: Debian **trixie**, архитектура **amd64**, полный набор
(LinuxCNC + RT-ядро + openbox + lightdm + alacritty + thunar + neovim).
Пакеты лягут в `debs/`, список — в `debs/packages.txt`.

Свой набор семян:

```bash
python3 fetch-packages.py linuxcnc-uspace linux-image-rt-amd64
```

Опции: `--suite`, `--arch`, `--mirror`, `--out`, `--no-recommends`.

## Шаг 2. Собрать флешку (data USB, не загрузочная)

Скопировать на флешку (FAT32/exFAT/ext4):

```
debs/              (папка с .deb)
setup-machine.sh
dotfiles/
```

## Шаг 3. На станке

```bash
sudo bash setup-machine.sh
```

Скрипт спросит перед началом:

1. **Очистить систему?** (внимание: удалит чужих пользователей и их `/home`,
   сторонние DE и приложения, `/etc/skel` — станок станет «как после установки»).
2. **RT-ядро загрузочным по умолчанию?**
3. **Перезагрузиться в конце?**
4. Покажет сводку и спросит подтверждение.

Флаги (не обязательны, переопределяют ответы):

| Флаг | Действие |
|------|----------|
| `--yes` | отвечать «да» на всё, без вопросов |
| `--skip-clean` | пропустить очистку системы |
| `--reboot` | перезагрузиться в конце |
| `--dry-run` | показать план, ничего не менять |

Что делает скрипт:

1. Preflight: Debian trixie amd64, root, наличие `debs/`.
2. **Чистка «как после установки»**: сносит чужие DE (GNOME/KDE/Xfce…),
   другие non-root пользователи (кроме `cnc`), чистит `/etc/skel`.
3. Установка пакетов из `debs/` офлайн.
4. Blacklist модуля `lp` (чтобы не мешал параллельному порту).
5. Пользователь `cnc` / пароль `cnc`, группы `sudo,dialout,plugdev,video,input,audio`.
6. dotfiles: openbox (клавиши, автозапуск), lightdm (запрос логина),
   Thunar (пункты ПКМ), хелперы в `~/bin`.
7. RT-ядро: grub → загрузка в `-rt-` ядро.

## Шаг 4. После перезагрузки

1. Войти `cnc` / `cnc` (greeter запрашивает логин/пароль).
2. **Первый запуск:** ввести распиновку станка в StepConf
   (`SUPER+F1` или `stepconf` в терминале) — пины по гайду станка
   (`machines/<модель>/linuxcnc-*-guide.md`).
3. Дальше LinuxCNC **запускается сам при входе** (конфиг найден автоматически).

### Клавиши

| Клавиша | Действие |
|---------|----------|
| `SUPER+Q` | терминал (alacritty) |
| `SUPER+E` | файловый менеджер (Thunar) |
| `SUPER+L` | запустить LinuxCNC |
| `SUPER+F1` | StepConf |
| `SUPER+C` | закрыть окно |
| `SUPER+1/2/3` | рабочие столы |
| `SUPER+SHIFT+1/2/3` | отправить окно на стол |

### Перенос файлов (ПКМ в Thunar)

- **«Копировать в linuxcnc/projects»** — G-code с флешки в `~/linuxcnc/projects`.
- **«Копировать на флешку»** — результат обратно на USB (автопоиск накопителя).

## Проверка установки

```bash
uname -r                     # должно содержать -rt-
which linuxcnc stepconf latency-test
dpkg -l | grep linuxcnc
latency-test                 # записать max jitter, ввести в StepConf
```

## Ограничения и оговорки

- **Версии пакетов:** набор качается для текущего `trixie` (stable). Если
  станок давно не обновлялся, apt может потребовать более свежую базовую
  библиотеку из набора (обычно это решается автоматически, набор самосогласован).
- **Пароль `cnc`** лежит открытым текстом в `setup-machine.sh` — это
  осознанное упрощение для домашнего станка. Для production смени пароль.
- **RT-ядро:** не удаляй старое ядро сразу — на всякий случай оно остаётся
  в grub (меню «Advanced options»).
- Лог установки: `/var/log/linuxcnc-setup.log`.
